> [!abstract] Distill(추출, 요약)
> - 이 볼트는 **CODE의 흐름**, **PARA의 배치 기준**, **제텔카스텐의 생각 연결**을 함께 사용한다.
> - **Distill은 각 노트 앞부분**에 구현되어 있다. 요약을 읽고 필요한 본문으로 들어간다.
> - 수집한 정보를 프로젝트와 일상에서 다시 사용하고, 얻은 생각을 연결해 다음 작업의 재료로 남긴다.

# 이 Second Brain을 사용하는 방법

이 시스템은 미래의 내가 정보를 쉽게 찾아 다시 생각하고 실행할 수 있도록 만든 작업 공간이다. 『세컨드 브레인』을 읽으며 정리한 내용과 제텔카스텐, Obsidian 사용 기록을 종합해서 현재의 폴더·속성·템플릿을 구성했다.


## 처음에는 이 세 가지부터

**기록 한 개 만들기 → 어디에 쓸지 정하기 → 다시 읽고 활용하기**를 한 번 해보면 전체 구조를 이해하기 쉽다. 모든 방법론을 먼저 익히거나 폴더를 전부 채울 필요는 없다.

| 지금 하려는 일 | 먼저 갈 곳 | 다음 행동 |
|---|---|---|
| 순간의 생각을 놓치고 싶지 않다 | Fleeting Notes | 짧게 적고 나중에 검토 |
| 읽은 자료를 기억하고 싶다 | Reference Notes | 출처와 내 이해를 적고 Distill 작성 |
| 끝낼 목표가 있다 | Projects | 첫 메모와 완료 기준 작성 |
| 꾸준히 관리할 책임이 있다 | Areas | 유지할 기준과 관련 프로젝트 연결 |
| 주제별 자료를 다시 찾고 싶다 | Resources | 해당 분야에 두고 필요한 곳에서 연결 |
| 생각 하나를 내 말로 설명할 수 있다 | Permanent Notes | 근거와 관련 생각을 연결 |
| 현재는 끝났거나 중단한 일이다 | Archives | 결과와 재사용할 자료를 남겨 보관 |

“왜 이 자료를 모았는가?”와 “다음에는 어디에 쓸 것인가?”를 정하면 위치를 결정하기 쉽다. 위치를 잠시 정하지 못하면 Capture에서 검토를 기다려도 된다.

## 실제 예시 네 개를 따라가기

1. [[예시 - 다음 행동을 남기는 아이디어]]에서 질문이 생긴 맥락을 본다.
2. [[예시 - 헤밍웨이 다리 참고 기록]]에서 출처 있는 자료와 자신의 질문을 구별한다.
3. [[📦P-예시 독서 기록 실험]]에서 질문을 실제로 시험할 계획과 다음 행동을 본다.
4. [[예시 - 다음 행동은 작업 재개를 돕는다]]에서 자기 말로 정리한 생각과 근거 연결을 본다.

예시를 읽은 뒤 자신의 관심사 하나로 같은 과정을 시도해보면 된다. 모든 노트를 반드시 영구 노트로 바꿔야 하는 과제는 아니다.

## 자주 헷갈리는 점

- **Reference와 Resources:** Reference는 출처 있는 자료라는 노트 유형이다. Resources는 주제별로 찾는 폴더다. Reference 노트를 Resources로 옮겨도 유형은 유지된다.
- **Distill과 Permanent:** Distill은 해당 노트를 빠르게 읽는 요약이다. Permanent는 한 가지 생각을 독립적으로 설명하고 연결한 별도 노트다.
- **Areas와 Resources:** Areas는 내가 책임지고 유지할 것, Resources는 참고할 지식이다. “건강 관리”와 “운동 방법 자료”를 구별하면 이해하기 쉽다.
- **Express와 결과물:** 영구 노트는 결과물의 재료가 될 수 있다. 글·발표·서비스는 프로젝트 안이나 외부 도구에서 완성될 수도 있다.
- **언더바 안내 노트:** `_`로 시작하는 파일은 이 구조의 사용 설명이다. 새 메모의 제목에 언더바를 붙일 필요는 없다.

## 방법론이 만나는 위치

| 개념 | 이 볼트의 구현 | 사용하는 이유 |
|---|---|---|
| Capture | 10. Capture와 임시·참고 노트 | 떠오르는 생각과 공명하는 자료를 빠르게 붙잡기 |
| Organize | 20. Organize 안의 PARA | 지금 쓰일 곳과 책임, 관심사에 따라 배치하기 |
| Distill | 일반 노트 맨 앞의 Distill 콜아웃 | 본문을 다시 읽기 전에 핵심과 쓸모를 파악하기 |
| Express | 프로젝트의 작업물과 30. Express의 영구 노트 | 지식을 자기 언어로 정리하고 실제 결과에 활용하기 |
| Zettelkasten | Fleeting → Reference와 함께 검토 → Permanent 및 관련 노트 연결 | 작은 생각을 발전시켜 재사용할 지식으로 만들기 |

CODE의 네 단계가 반드시 네 개 폴더여야 하는 것은 아니다. **이 볼트에서는 Distill을 노트 안에 배치**했다. 정리된 자료를 사용할 때마다 핵심을 다듬을 수 있고, 요약과 본문의 맥락도 함께 유지할 수 있다. 자세한 방법은 [[_Distill-핵심-추출]]에 있다.

영구 노트는 자기 생각을 표현한 지식 단위이며, 글·발표·서비스 같은 결과물의 재료가 된다. Express는 이러한 생각을 실제로 사용하는 활동까지 포함한다. 결과물이 언제나 Express 폴더 안에 있어야 하는 것은 아니다.

## 처음 시작하는 순서

1. [[_Capture]]를 읽고 생각 한 개 또는 자료 한 개를 기록한다.
2. 내 생각은 [[_Zettelkasten-FleetingNotes]], 외부 자료는 [[_Zettelkasten-ReferenceNotes]]의 방식을 따른다.
3. [[_Distill-핵심-추출]]을 참고해 미래의 내가 읽을 요약을 노트 맨 위에 쓴다.
4. [[_Organize]]의 기준으로 사용할 곳을 정한다.
5. 독립적으로 설명할 생각이 생기면 [[_Zettelkasten-PermanentNotes]]로 발전시키고, [[_Projects]]에서 결과물에 활용한다.
6. [[_Periodic-Notes]]의 리뷰로 수집함과 진행 중인 일을 다시 살핀다.

모든 메모가 이 순서를 끝까지 거칠 필요는 없다. 필요한 자료를 바로 프로젝트에서 쓰거나, 기존 영구 노트를 보며 새로운 질문을 Capture에 기록할 수도 있다.

## 하나의 메모가 활용되는 예시

다음은 사용법을 보여주는 가상의 예시다.

| 순간 | 기록과 행동 |
|---|---|
| 생각이 떠오름 | Fleeting에 “책을 읽어도 다음 날 핵심이 기억나지 않는다” 기록 |
| 자료를 읽음 | Reference에 읽은 글의 출처와 핵심, 내 질문 기록 |
| 핵심을 추출함 | 자료 노트의 Distill에 “읽은 뒤 자기 말로 설명하는 연습” 요약 |
| 적용할 일을 정함 | Projects에 “4주간 독서 기록법 실험”을 만들고 관련 자료 연결 |
| 생각을 발전시킴 | Permanent에 “독서 기록은 다음 행동과 연결될 때 다시 읽힌다”라는 주장과 근거 작성 |
| 작업을 이어감 | 프로젝트의 The Hemingway Bridge에 다음 실험과 확인할 질문 기록 |
| 마침 | 실험 결과를 정리하고 프로젝트를 Archives로 이동; 배운 원리는 다음 작업에서 재사용 |

## 폴더·속성·링크를 함께 사용하기

폴더는 주로 어디서 사용할지, 속성은 어떤 종류의 노트인지와 검색 조건을 나타낸다. 연결은 위키링크로 표현하고, 왜 관련이 있는지도 문장으로 남긴다. 태그는 frontmatter의 tags에 기록한다.

관련 노트가 많아지면 프로젝트 메인 노트나 책 메인 노트가 출발점이 된다. 그래프의 모양을 위해 무작정 연결하기보다, 다시 찾거나 생각을 전개하는 데 필요한 연결을 만든다.
